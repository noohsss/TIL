# HTTP (HyperText Transfer Protocol)

HTTP는 **클라이언트(Client)와 서버(Server)가 데이터를 주고받기 위한 통신 규약(Protocol)**이다.
웹 브라우저가 서버에 요청(Request)을 보내고, 서버가 응답(Response)을 반환하는 방식으로 동작한다.

---

## HTTP Method

HTTP Method는 **클라이언트가 서버에 어떤 작업을 요청하는지**를 나타낸다.

| Method | 설명         | 예시           |
| ------ | ---------- | ------------ |
| GET    | 데이터를 조회    | 게시글 목록 조회    |
| POST   | 새로운 데이터 생성 | 회원가입, 게시글 작성 |
| PUT    | 데이터를 전체 수정 | 회원 정보 전체 수정  |
| PATCH  | 데이터를 일부 수정 | 닉네임만 변경      |
| DELETE | 데이터 삭제     | 게시글 삭제       |

### GET과 POST 차이

| GET         | POST          |
| ----------- | ------------- |
| 조회 목적       | 생성 목적         |
| URL에 데이터 포함 | Body에 데이터 포함  |

---

## HTTP Status Code

HTTP 상태 코드는 **서버가 요청 처리 결과를 숫자로 표현한 것**이다.

### 2xx (Success)

* **200 OK** : 요청 성공
* **201 Created** : 생성 성공
* **204 No Content** : 성공했지만 반환할 데이터 없음

### 4xx (Client Error)

* **400 Bad Request** : 잘못된 요청
* **401 Unauthorized** : 인증 필요
* **403 Forbidden** : 접근 권한 없음
* **404 Not Found** : 요청한 리소스를 찾을 수 없음

### 5xx (Server Error)

* **500 Internal Server Error** : 서버 내부 오류
* **502 Bad Gateway** : 게이트웨이 오류
* **503 Service Unavailable** : 서버 사용 불가

## URL (Uniform Resource Locator)

URL은 **인터넷에서 특정 자원의 위치를 나타내는 주소**이다.

### URL 구조

```
https://www.example.com:443/users?id=1#profile
```

| 구성 요소                                     | 설명                   |
| ----------------------------------------- | -------------------- |
| https                                     | 프로토콜(Scheme)         |
| [www.example.com](http://www.example.com) | 도메인(Domain)          |
| 80                                       | 포트 번호(생략 가능)         |
| /users                                    | 경로(Path)             |
| ?id=1                                     | 쿼리 스트링(Query String) |

### Query String

* `?`로 시작한다.
* `key=value` 형태이다.
* 여러 개는 `&`로 연결한다.

예시

```
/users?id=1&name=kim
```

## Port

포트(Port)는 **하나의 컴퓨터에서 실행되는 여러 프로그램을 구분하기 위한 논리적인 번호**이다.

## Cookie & Session

로그인 상태를 유지하기 위해 **Cookie와 Session**을 사용한다.

### Cookie

쿠키는 **브라우저(클라이언트)에 저장되는 데이터**이다.

#### 특징

* 클라이언트에 저장된다.
* 서버 요청 시 자동으로 함께 전송된다.
* 사용자 설정이나 로그인 정보를 저장할 수 있다.
* 사용자가 삭제할 수 있다.

#### 장점

* 서버의 저장 공간을 사용하지 않는다.
* 구현이 간단하다.

#### 단점

* 클라이언트에 저장되므로 변조될 가능성이 있다.
* 민감한 정보를 직접 저장하는 것은 위험하다.

---

### Session

세션은 **서버에 사용자 정보를 저장하는 방식**이다.

#### 동작 과정

1. 사용자가 로그인한다.
2. 서버가 Session을 생성한다.
3. Session ID를 쿠키에 담아 브라우저에 전달한다.
4. 이후 요청마다 Session ID가 서버로 전달된다.
5. 서버는 Session ID를 조회하여 사용자 정보를 확인한다.

#### 장점

* 실제 사용자 정보는 서버에 저장되어 비교적 안전하다.
* 로그인 인증에 많이 사용된다.

#### 단점

* 서버 메모리를 사용한다.
* 사용자가 많아질수록 서버 부담이 증가한다.

---

### Cookie와 Session 비교

| Cookie        | Session               |
| ------------- | --------------------- |
| 저장 위치: 클라이언트  | 저장 위치: 서버             |
| 저장 내용: 데이터 자체 | 저장 내용: 사용자 정보         |
| 보안: 상대적으로 낮음  | 보안: 상대적으로 높음          |
| 서버 자원 사용: 적음  | 서버 자원 사용: 많음          |
| 저장 기간: 설정 가능  | 보통 브라우저 종료 또는 만료 시 종료 |
