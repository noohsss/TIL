# 개발 기획과 TDD

## 개발 전에 기획이 필요한 이유

기획은 **무엇을, 누구를 위해, 어디까지 만들지** 먼저 정하는 과정이다.

기획 없이 바로 개발하면 기능이 계속 추가되거나 화면과 데이터 구조가 자주 바뀌어 재작업이 늘어난다. 반대로 목표와 범위를 먼저 정하면 개발 기준이 명확해지고 팀원 간의 이해 차이도 줄일 수 있다.

개발 전에는 다음 내용을 확인한다.

- 해결할 문제와 사용자
- 핵심 기능과 우선순위
- 화면 흐름과 사용자 경험
- 필요한 데이터와 API
- 기술 스택과 배포 방식
- 완료 조건과 테스트 방법

기획은 처음부터 완벽한 문서를 만드는 일이 아니다. 먼저 작은 범위의 MVP를 정하고, 구현과 피드백을 반복하며 구체화한다.

## TDD

TDD(Test-Driven Development)는 실제 코드를 작성하기 전에 테스트를 먼저 만들고, 테스트를 통과하도록 코드를 구현하는 개발 방식이다.

```text
Red → Green → Refactor
```

1. **Red**: 원하는 동작을 테스트로 작성하고 실패를 확인한다.
2. **Green**: 테스트를 통과하는 최소한의 코드를 작성한다.
3. **Refactor**: 테스트가 통과하는 상태를 유지하며 코드를 개선한다.

### 장점

- 요구사항을 테스트 가능한 동작으로 구체화할 수 있다.
- 코드 변경으로 기존 기능이 깨지는 회귀 오류를 빠르게 발견한다.
- 테스트하기 쉬운 작은 단위로 코드를 설계하게 된다.

### 주의점

- 구현 방식이 아니라 사용자가 기대하는 동작을 테스트한다.
- 외부 API와 UI처럼 변동이 큰 부분은 단위 테스트와 통합 테스트를 구분한다.
- 모든 코드를 억지로 테스트하기보다 오류 위험과 중요도가 높은 기능부터 적용한다.
