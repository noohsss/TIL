# 배포와 클라우드 서비스

## 배포

배포(Deploy)는 개발한 애플리케이션을 서버에 올려 **사용자가 접근할 수 있는 상태로 만드는 과정**이다.

일반적인 흐름은 코드 빌드 → 테스트 → 서버 반영 → 동작 확인 → 모니터링 순서이다.

## 주요 서비스

| 서비스 | 핵심 역할 |
| --- | --- |
| Vercel | 프론트엔드와 서버리스 애플리케이션의 간편한 배포 |
| AWS | 서버, 데이터베이스, 스토리지 등 폭넓은 클라우드 인프라 제공 |
| GCP | 컴퓨팅, 데이터, AI 중심의 다양한 클라우드 서비스 제공 |
| Supabase | 데이터베이스, 인증, 스토리지, API를 제공하는 백엔드 플랫폼 |

서비스는 프로젝트 규모, 비용, 운영 난이도, 필요한 기능을 기준으로 선택한다.

### Supabase를 활용한 배포

Supabase를 사용하면 별도의 백엔드 서버를 처음부터 구축하지 않고도 웹이나 앱에 필요한 데이터베이스와 인증 기능을 연결할 수 있다. 프론트엔드는 Vercel 등에 배포하고, 백엔드 기능은 Supabase에서 제공하는 방식으로 함께 사용할 수 있다.

다만 운영 환경에서는 비밀키를 클라이언트 코드에 노출하지 않고, 데이터 접근 권한 정책을 반드시 설정해야 한다.

## AI Agent를 활용한 배포

AI Agent는 설정 작성, 명령 실행, 오류 분석 같은 배포 작업을 자동화할 수 있다.

### 주의점

- 운영 환경의 비밀키와 접근 권한은 최소한으로 제공한다.
- 배포 전 테스트와 변경 내용을 사람이 검토한다.
- 로그와 비용을 모니터링한다.
- 장애에 대비해 이전 버전으로 되돌리는 방법을 준비한다.
- 데이터 삭제나 운영 환경 변경은 반드시 승인 절차를 둔다.

## Vercel 환경변수 설정

환경변수는 API 키나 서비스 주소처럼 환경마다 달라지는 값을 소스 코드 밖에서 관리하는 방법이다.

Vercel Dashboard에서 **Project → Settings → Environment Variables**로 이동해 이름과 값을 등록한다.

| 환경 | 적용 대상 |
| --- | --- |
| Development | 로컬 개발 환경 |
| Preview | 운영 브랜치가 아닌 브랜치의 미리보기 배포 |
| Production | 운영 브랜치 또는 운영 배포 |

환경변수를 변경해도 이미 완료된 배포에는 적용되지 않으므로 새로 배포해야 한다.

로컬에서는 다음 명령으로 Development 환경변수를 내려받을 수 있다.

```bash
vercel env pull
```

### 주의사항

- `.env`와 `.env.local`은 Git에 커밋하지 않는다.
- 비밀키를 클라이언트에 노출되는 환경변수에 넣지 않는다.
- 개발, 미리보기, 운영 값을 분리한다.
- 키를 노출했다면 값을 삭제하는 것에 그치지 않고 해당 키를 폐기하고 다시 발급한다.

[Vercel 환경변수 공식 문서](https://vercel.com/docs/environment-variables)
