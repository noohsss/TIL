# n8n 학습 정리 - 표현식과 HTTP/API 기초

## 개요

DAY04에서는 고정값이 아닌 **흐르는 데이터**를 워크플로우에서 다루는 방법을 배웠다.

표현식으로 이전 노드의 데이터를 꺼내 쓰고, HTTP/API의 기본 구조를 이해한 뒤, 처음 보는 공개 API를 문서만 보고 스스로 연결하는 것이 목표였다.

# 1. 표현식(Expression) 기초

## 표현식이란

`{{ }}` 로 감싸 입력란에 쓰는 작은 JavaScript 코드 조각이며, 실행 시점에 실제 값으로 치환된다.

## 자주 쓰는 표현식 기본형

- 현재 아이템 필드 참조: `$json.필드명`
- 중첩 객체는 점(.), 배열은 인덱스로 접근
- 날짜: `$now.format(...)`
- 사칙연산 등 계산도 가능

## 표현식은 지연 평가(Lazy Evaluation)다

- 저장 시점의 값으로 굳지 않고, 그 노드가 실제로 실행되는 순간의 값으로 치환됨
- 아이템이 여러 개면 노드가 그만큼 반복 실행됨 -> n8n의 핵심 실행 모델("아이템 단위 반복")

## 흔한 실수 3가지

- 표현식 모드(fx 토글)를 켜지 않음
- 아직 한 번도 실행하지 않은 앞 노드를 참조함
- 필드명 대소문자/철자 오류로 조용히 빈 값이 됨

# 2. 표현식 심화

## 다른 노드의 데이터 참조

- `$('노드명').item.json...` 으로 특정 노드의 출력을 직접 지목
- 노드 이름을 바꾸면 참조가 깨지므로, 초반에 의미 있게 짓고 유지해야 함

## 날짜/문자열 가공

- 어제 날짜 구하기, 문자열 자르기, 포함 여부 확인, 숫자 포맷팅, 배열 이어붙이기 등 JS 메서드를 그대로 활용

## undefined가 나오는 3가지 원인

- 경로 오타
- 중간 단계 누락(예: 응답이 `body` 한 겹 더 감싸져 있음)
- 다른 노드의 값이 필요한데 현재 아이템 참조로 지칭함
- 해결법은 항상 동일: 앞 노드 출력의 실제 JSON 구조를 눈으로 확인하며 경로를 한 칸씩 따라가기

# 3. HTTP와 API 기본 구조

## API = 프로그램 간의 주문창구

- 요청(Request) = URL + 메서드 + 파라미터
- GET = 조회, POST = 생성/전송
- 응답(Response) = 보통 JSON으로 돌아옴
- 상태코드 = 200 성공 / 401 인증실패 / 404 없음 / 429 과다요청 / 500 서버오류

## HTTP Request 노드 = curl/fetch의 GUI판

- Method/URL/Header/Body/Query가 curl의 `-X`, URL, `-H`, `-d`, 쿼리 파라미터에 각각 대응
- 차이점은 응답이 터미널 텍스트가 아니라 다음 노드로 흘러가는 구조화된 데이터라는 것 -> 파이프라인 구성이 가능해짐

## 응답 JSON 읽는 법

- 가장 바깥 괄호부터: `{}` 는 객체(키-값), `[]` 는 배열(순서 있는 목록)
- 원하는 값까지 경로로 적기(예: `rates.KRW`)
- 배열이 나오면 인덱스(0부터)로 접근

# 4. 실전 API 연결에서 얻은 인사이트

## "호출 -> 추출 -> 가공 -> 발송" 흐름의 의미

- 외부의 실시간 데이터가 워크플로우에 처음으로 들어온 단계
- API 응답 -> 필요한 값 추출 -> 사람이 읽을 문장으로 가공 -> 채널로 발송하는 흐름은 이후 미니 프로젝트(뉴스 Agent 등)의 축소판

## 인증이 필요한 API

- Authentication 옵션 또는 Header에 키를 실어 전달
- API Key는 URL이나 워크플로우 본문에 절대 하드코딩하지 않고 n8n Credential로 저장하는 것이 원칙

# 5. 데이터 변형 패턴 3종

| 패턴 | 상황 | n8n 도구 |
|------|------|----------|
| 펼치기 (1 → N) | 배열로 온 응답을 아이템 여러 개로 분리 | Split Out |
| 합치기 (N → 1) | 여러 아이템을 하나의 목록으로 재구성 | Aggregate / Code |
| 합류 (A + B) | 서로 다른 두 흐름을 하나로 연결 | Merge |

## 파이프라인의 기본 리듬

펼쳐서 건별로 처리하고, 마지막에 합쳐서 한 번에 발송한다.
