# 프로젝트 2 — 금융 뉴스 브리핑 Agent

매일 오전 8시 30분(Asia/Seoul)에 한국경제·매일경제·연합뉴스 경제 RSS를 수집하고, 오늘 기사만 선별한 뒤 Google Sheet 발송 이력과 대조합니다. 신규 금융 기사만 Gemini AI Agent로 요약·분류하고 중요도 4 이상을 Discord 메시지 한 건으로 발송합니다.

## 파일

- `financial_news_briefing_n8n.json`: n8n에서 바로 Import할 워크플로우

## 최초 설정

### 1. Google Sheet 준비

본인 소유 Google Sheet에 `발송이력` 탭을 만들고 첫 번째 행에 아래 헤더를 순서대로 입력합니다.

```text
sent_at | briefing_date | article_id | canonical_url | source | title | published_at | category | importance | summary | needs_review
```

`financial_news_briefing_n8n.json`을 n8n에 Import한 뒤 두 Google Sheets 노드에서 다음을 설정합니다.

1. `REPLACE_WITH_SPREADSHEET_ID`를 본인 Google Sheet ID로 교체
2. Google Sheets OAuth2 Credential 연결
3. Sheet 이름이 `발송이력`인지 확인

Google Sheet URL이 `https://docs.google.com/spreadsheets/d/ABC123/edit`라면 ID는 `ABC123` 부분입니다.

### 2. Gemini 설정

`Gemini Chat Model` 노드에 본인의 Google Gemini API Credential을 연결합니다. 기본 모델은 `models/gemini-2.5-flash`, temperature는 `0.1`입니다. 해당 모델이 계정이나 설치된 n8n 버전에서 보이지 않으면 노드의 모델 목록에서 사용 가능한 Flash 모델을 다시 선택합니다.

### 3. Discord 설정

개인 Discord 채널의 `채널 설정 → 연동 → 웹후크 → 새 웹후크`에서 Webhook URL을 복사합니다. `Discord 브리핑 1회 발송` 노드의 아래 URL을 실제 URL로 교체합니다.

```text
https://discord.com/api/webhooks/REPLACE_ME/REPLACE_ME
```

Discord embeds를 사용하므로 기사별 제목, 요약, 원문 링크, 카테고리, 중요도가 한 메시지 안에 표시됩니다. Discord의 메시지당 embed 개수 제한에 맞춰 중요도순 최대 10건을 한 메시지로 보냅니다.

### 4. 실행 확인

1. `수동 테스트`로 실행
2. 세 RSS 노드 중 일부가 실패해도 나머지 피드로 계속 진행되는지 확인
3. Discord 메시지와 Google Sheet 누적 행 확인
4. 같은 날 다시 수동 실행하여 이미 발송된 기사가 LLM 전에 제거되는지 확인
5. 정상 확인 후 워크플로우를 Active로 전환

## 설계 판단

### 고유값과 중복 제거

`article_id`는 정규화한 `canonical_url`입니다. URL fragment와 `utm_*`, `fbclid`, `gclid`, `ref` 같은 추적 파라미터를 제거하고 쿼리 순서를 정렬합니다. 언론사 RSS에서 기사 원문 URL은 게시물의 안정적인 식별자이고 제목 수정에도 영향을 받지 않으며, 해시 충돌 가능성도 없기 때문입니다.

중복 제거는 Google Sheet 이력 조회 직후, Gemini 호출 전에 수행합니다. 발송 성공 후 중요도 4 이상으로 실제 발송된 기사만 시트에 누적하므로 중요도 1~3 기사는 다음 날 재등장하더라도 그날 기사 필터에서 제외됩니다.

### 금융 키워드 필터 위치

키워드 필터는 Gemini 호출 전입니다. 제목과 RSS 설명에서 금융 포함 키워드를 찾고, 연예·스포츠·날씨 강한 제외어가 있으면서 금융 근거가 약한 기사를 제거합니다. 이 배치로 비금융 기사에 대한 토큰 비용과 LLM 오분류 가능성을 동시에 낮춥니다. 키워드가 있는 기사에 한해서 Gemini가 의미 기반 중요도와 카테고리를 판단하므로 규칙 필터만 사용하는 것보다 정확도를 보완합니다.

### 검증 안전판

Structured Output Parser와 후처리 Code 노드를 함께 사용합니다. 후처리에서 아래를 재검증합니다.

- `summary`: 빈 문자열이 아니며 3문장 이하
- `importance`: 1~5 범위 정수
- `category`: 증시 / 금리 / 환율 / 부동산 / 기업 / 정책 / 기타
- `needs_review`: boolean

검증 실패 시 `needs_review=true`로 바꾸고, 잘못된 중요도는 1로 낮춰 자동 발송에서 제외합니다. RSS 설명이 부족하거나 입력 사실만으로 판단하기 어려울 때도 프롬프트가 `needs_review=true`를 요구합니다.

### 중요 기사 0건 경로

두 종류의 정상 알림이 있습니다.

- Gemini 호출 전 후보 0건: 수집·오늘 기사·중복 제거·키워드 제외 건수를 알림
- Gemini 분석 후 중요도 4 이상 0건: 분석 건수와 함께 정상 완료를 알림

따라서 사용자는 “오늘 중요 뉴스가 없음”과 “워크플로우 미실행/장애”를 구분할 수 있습니다.

## 사용 RSS

- 한국경제 경제: `https://www.hankyung.com/feed/economy`
- 매일경제 경제: `https://www.mk.co.kr/rss/30100041/`
- 연합뉴스 경제: `https://www.yna.co.kr/rss/economy.xml`

RSS 제공사의 URL이나 XML 형식은 향후 변경될 수 있으므로 운영 중 `invalid_or_feed_error` 증가와 n8n 실행 로그를 확인합니다.
